Roles

Three roles, three sets of permissions

Access is checked on every request. What you can do depends on your role and on whether the content is yours or has been shared with you.

Unauthenticated user

Not signed in yet.

  • Register an account with a unique email address
  • Sign in if an account already exists
  • Recover an account with a magic link
Registered user

Signed in with password and one-time code.

  • Upload, organize, rename, download and delete own files and folders
  • Upload new versions of own files
  • Create groups and manage their membership
  • Share files and folders with users or groups, and revoke sharing
  • Receive notifications, view activity history and account analytics
  • Submit a request to increase the storage quota
Administrator

Signed in with administrator privileges.

  • See every user with their current quota and storage usage
  • See all incoming quota increase requests
  • Approve a request, which updates the user's quota
  • Reject a request without changing the quota
  • Administrative activity is written to the audit log
Features

What the platform does

Everything below is enforced on the server, not just in the browser.

Registration with confirmation

A unique email address, first name, last name, password and repeated password are required. A strong password is enforced and the registration must be confirmed. Every new account receives a default storage quota.

Two-factor sign-in

Signing in requires your password and a one-time code sent to your email address. Account recovery is handled with a magic link.

Password policy and reset

A password can only be changed once it is at least one day old. Passwords expire after 60 days, after which sign-in is blocked until a reset. Resets use a short-lived link sent to the known email address.

Folders at any depth

Create a folder in the root or inside any subfolder. Folders form a hierarchy of arbitrary depth, and you can browse into any of them.

Upload and new versions

Upload files into any of your folders. The assigned quota is checked before the upload is accepted. Uploading a new version replaces the file content and records the time of the last modification.

Browse and rename

Opening a folder shows its subfolders and files. The name of any file or folder you own can be changed.

User groups

Create groups, add members and remove them again. Groups exist so that content can be shared with several people at once and kept in sync as membership changes.

Sharing with users and groups

Share a file or a folder with a single user or with one of your groups. Sharing a folder applies to everything inside it. Your profile shows what you have shared and with whom, and what has been shared with you — and you can revoke at any time.

Clear limits for recipients

A user you share with can view and download the content. They cannot delete it and they cannot upload new versions of it. Those actions stay with the owner.

Download and preview

Download a file or open its metadata in the browser. Access rights are verified before either action. Text files and images can be previewed directly in the browser.

Search scoped to your access

Search files and folders by name, powered by Elasticsearch with partial matching and tolerance for typing mistakes. Results only ever include your own content, content shared directly with you, content shared through a group you belong to, and content inside a shared parent folder.

Notifications

You are notified when someone shares a file or folder with you, when a new file is added to a folder shared with you, and when a new version of a file shared with you is uploaded.

Storage quota and admin approval

Your quota is assigned at registration and checked on every upload. If you need more space you submit a request stating the desired value. An administrator sees all users with their quota and usage and can approve or reject each request.

Activity history

Uploads, renames, deletions and downloads, creation and revocation of shares, and folder and group operations are all recorded and shown in your history. The history is built from an event log rather than a mutable table.

Account analytics

Total storage used, the number of files per type, the five files you accessed the most, and the number of files shared with you. Analytics are computed from the same event stream as the activity history.

Deletion that cleans up after itself

Deleting a folder deletes everything inside it. File content, metadata, sharing information and related notifications are all removed. The operation runs as a saga so that a partial failure does not leave orphaned data behind.

How it works

From registration to a shared folder

Three steps, each with its own security check.

1
Register and confirm

Enter your name, a unique email address and a strong password twice. Confirm the registration, and your account is created with a default storage quota.

2
Sign in with two factors

Enter your password, then the one-time code that arrives by email. If your password has expired, sign-in is blocked until you reset it through the emailed link.

3
Upload, organize and share

Build your folder structure, upload files within your quota, create groups, and share files or folders with users and groups. Notifications keep everyone informed.

Security

Controls applied to every request

Security is enforced in the API gateway and in each service, on the server side, regardless of what the client sends.

Authentication
  • Password plus a one-time code sent by email
  • Magic-link account recovery
  • Password change only after one day of use
  • 60-day password expiry blocks sign-in until reset
Authorization
  • Checked for every request, on the server
  • Applies to downloads and previews, not just the UI
  • State kept on the client is encrypted and integrity-protected
Input validation
  • String checks, whitelisting and boundary checking
  • Numeric and special-character validation
  • Validation on both the client and the server
  • Output encoding as protection against XSS and injection
Safe file handling
  • User privileges checked before any file operation
  • File type whitelisting on upload
  • Integrity verification of stored files
Transport and credentials
  • HTTPS between the client and the API gateway
  • HTTPS between services
  • Sensitive parameters are not sent in the URL
  • Passwords stored hashed and salted
Logging and audit trail
  • Validation failures and access-control failures
  • Successful and failed sign-in attempts
  • Invalid or expired session tokens, failed backend TLS
  • Administrator actions and unexpected state changes
  • Log rotation, restricted access, no sensitive data or stack traces
Abuse protection
  • Rate limiting of transactions per user against DoS
  • Timeouts on every outgoing request
  • Circuit breaker and retry so failures stay contained
Vulnerability analysis

A security report documents which tools were used to look for vulnerabilities, what was found, how it could be exploited, and how the issue is mitigated.

Attack demonstrations

The platform ships with mechanisms that demonstrate XSS, SQL injection, brute-force and DoS attempts, together with the defenses that stop them.

Architecture

Five services behind one gateway

Every client request enters through the REST API gateway. Services talk to each other synchronously where an answer is needed immediately, and asynchronously for everything that can be derived from events.

Users
Document database

Stores credentials, roles, first and last name, and storage quota. Handles registration and sign-in.

Files
Document database + object store

Keeps file and folder metadata: name, type, size, owner, parent folder, timestamps and a reference to the content. Content itself lives in the object store.

Sharing
Graph database

Holds the access graph: who may see which file or folder, and which groups exist and who belongs to them. Reacts to events from the Files service.

Notifications
Wide-column database

Stores and delivers notifications. Listens for sharing events and new-version events to decide which users to inform.

Analytics
Event-sourced read model

Records activity history and computes analytics for files and storage usage by consuming events from the other services.

Supporting infrastructure
Cache, search, object store

Redis caches the most frequently accessed files. Elasticsearch indexes files and folders for search. The object store holds file content.

FAQ

Common questions

How the platform behaves in the situations that come up most.

Sign-in is combined: you enter your password, and a one-time code is sent to your email address. Both are required. If you lose access to your account, recovery is available through a magic link.

A password is valid for 60 days. Once it expires, sign-in is blocked until you set a new one through the reset link sent to your email address. This makes the account auditable: an expired credential cannot be used to get in. A password can only be changed after it has been in use for at least one day.

Every account is created with a default quota, and every upload is checked against it. If you need more space, submit a request stating the value you want. An administrator reviews it and either approves it, which updates your quota, or rejects it.
